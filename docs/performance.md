# 속도 개선 · 2026-11-08

## 확인한 병목

- 운영 사이트 응답의 `x-vercel-id`는 `icn1::iad1` 경로였다. 한국 엣지에서 미국 동부 함수로 넘어가고 있었다.
- DB 호스트의 공개 IPv6 주소를 AWS 공개 IP 대역과 대조한 결과 `ap-northeast-2`(서울)였다. 서버와 DB 사이의 장거리 왕복을 줄이도록 `vercel.json`에 `icn1`을 지정했다. **새 배포부터 반영된다.**
- 프로젝트의 공개 JWKS는 ES256이다. Proxy에서는 `getClaims()`로 서명 검증·세션 갱신을 처리한다. 보호된 API의 `getUser()`, 학교 계정 확인, `is_member()`, RLS 검사는 유지한다.

## 적용한 변경

- 게시글 목록·상세·내 게시글 조회를 같은 세션의 메모리 캐시와 진행 중인 요청으로 공유한다. 캐시 신선도는 15초, 최대 20개 조회다. 저장 후 캐시를 비우고, 저장 이전에 시작한 응답은 재조회해 최신 결과를 사용한다.
- 초기 화면이 준비된 뒤 분실물·내 게시글·가장 최근 채팅방을 백그라운드에서 준비한다. 채팅의 같은 메시지 조회도 공유하고 최근 응답은 5초간 재사용한다.
- 전체 프로필 최대 5,000명 조회를 대화 참여자 조회로 좁히고, 게시글 작성자는 게시글 조회에 함께 가져온다.
- 기본 초기 데이터에서 전체 최근 메시지 500개 조회를 제거했다. 열린 방만 최근 50개를 갱신하고, 이전 대화는 더 보기를 통해 가져온다. 구형 inbox 함수에 미리보기·미확인 개수가 없을 경우 기존 조회를 호환용으로 유지한다.
- 수신 메시지를 Realtime 이벤트로 즉시 반영한다. 전송·읽음 처리 결과도 바로 반영하고, 그때마다 전체 스냅샷을 재조회하지 않는다. 과거 스냅샷이 새 상태를 되돌리지 않게 보호한다.
- 목록 사진은 320/640px WebP로 제공한다. 인증·미디어 행의 RLS 검사를 통과한 뒤에만 최대 16MiB의 서버 메모리 캐시를 사용한다. 목록 사진은 브라우저에 private 60초 캐시하고 `Vary: Cookie`를 적용한다. 원본 응답은 계속 `private, no-store`다. 로그아웃 시 브라우저 캐시 삭제 헤더도 보낸다.
- 로그인 로고를 앱 공통 UI에서 분리하고, 글 작성 폼과 Select 관련 코드는 작성·편집할 때 불러온다.
- 데이터·게시글 API에 `Server-Timing: auth, db`를 추가했다. 재배포 후 개발자 도구에서 인증 시간과 쿼리 시간을 구분할 수 있다.

## 검증과 한계

- 성능 브라우저 검사: 동일 조회 공유, 재방문 캐시, 전송·읽음 후 전체 재조회 없음, 응답 역전 시 상태 보존을 확인했다.
- 기존 채팅 입력·스크롤, 설치 안내, 알림, 폼 선택 검사도 통과했다.
- API 테스트로 초기 조회 범위와 비로그인 차단을 확인했다. 사진 캐시가 채워져 있어도 행 접근이 거절되면 404가 반환되는 것을 확인했다.
- 합성 1600px 이미지의 320px 축소 시험은 3,502 → 220 bytes였다. 이는 축소·다운로드 공유 기능 검증용이며 실제 사진 전체의 압축률을 뜻하지 않는다.
- 실제 PostgREST에 작성자 관계를 포함한 0행 조회를 실행해 새 관계 조회 문법이 유효함을 확인했다.
- 운영 DB의 인덱스/실행 계획은 관리 연결 권한이 없어 직접 검사하지 못했다. DB 스키마·RLS는 변경하지 않았다. 운영 로그인 세션을 이용한 전체 흐름의 배포 전후 실측도 아직 하지 않았다.
- 서버 지역 변경은 재배포 후 `x-vercel-id`와 API `Server-Timing`으로 최종 확인해야 한다.
