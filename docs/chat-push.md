# 채팅 웹 푸시 설정

Firebase나 FlareLane 없이 표준 Web Push로 새 채팅만 알립니다. 알림 제목은 보낸 사람의 Google 계정 이름, 본문은 메시지 미리보기(최대 160자)와 대화에 저장된 게시글 제목입니다. 사진만 보낸 경우에는 ‘사진을 보냈어요.’로 표시합니다. 이미 읽은 메시지는 서버 확인 시 발송하지 않고, 같은 채팅방 알림은 기기에서 묶입니다. 본문 줄바꿈과 실제 표시 길이는 기기 및 OS에 따라 달라질 수 있습니다.

## 배포 준비

1. 대상 Supabase 프로젝트에 `supabase/migrations/20261020063207_chat_push.sql`을 적용합니다. `push_subscriptions`, `push_deliveries`는 RLS를 켜고 서버 역할만 접근하도록 제한했습니다. 기존 채팅 테이블은 수정하지 않습니다.
2. `npx web-push generate-vapid-keys`를 한 번 실행합니다. 출력된 공개키를 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, 비밀키를 `VAPID_PRIVATE_KEY`로 등록합니다. `VAPID_SUBJECT`에는 실제 연락 가능한 `mailto:` 주소 또는 서비스의 HTTPS URL을 넣습니다.
3. 로컬 `.env.local`과 Vercel 환경변수에 설정합니다. 기존 `SUPABASE_SECRET_KEY`도 필요합니다. `APP_URL`은 배포의 정확한 HTTPS 주소여야 합니다. 비밀키는 절대로 `NEXT_PUBLIC_` 이름으로 등록하지 않습니다.
4. Vercel을 다시 빌드·배포합니다. 공개키가 빌드에 포함되므로 환경변수 변경만으로는 부족합니다. 운영 도메인을 고정해 사용하고 키는 보관합니다. 키를 바꾸면 기존 구독은 재설정이 필요할 수 있습니다.

키가 설정되지 않으면 채팅은 그대로 동작하고 설정 화면에 알림 준비 중으로 표시됩니다. 이 저장소 작업에서는 운영 DB 또는 Vercel 환경변수를 변경하지 않았습니다.

## 사용자 흐름

- 채팅 목록에서 **채팅 알림 받기**를 누르고 브라우저 권한을 허용합니다. 브라우저/기기별로 설정해야 합니다.
- iPhone/iPad는 iOS/iPadOS 16.4 이상이 필요합니다. Safari 공유 메뉴 → **홈 화면에 추가** → 추가된 아이콘으로 실행 → 채팅 목록에서 알림 켜기 → 권한 허용 순서입니다. 카카오톡 등의 인앱 브라우저에서는 Safari로 먼저 열어주세요.
- **이 기기 알림 끄기**로 해당 기기만 해제합니다. 로그아웃하면 현재 기기 연결을 해제하고, 탈퇴하면 모든 기기를 해제합니다. 재로그인 후 채팅 목록을 열면 남아 있는 브라우저 구독을 현재 회원에게 다시 연결합니다.
- 알림 차단은 앱이 강제로 해제할 수 없습니다. 기기/브라우저 설정에서 허용해야 합니다. 집중 모드와 네트워크 상태도 수신 시점에 영향을 줍니다.

## 검증

채팅 목록의 **테스트 알림**은 서버 발송을 거치지 않고 현재 브라우저에서 알림을 표시합니다. 이것도 보이지 않으면 브라우저/OS의 알림 허용·집중 모드부터 확인합니다. 테스트 알림은 보이는데 채팅 알림만 보이지 않으면 개발 서버의 푸시 제공업체별 접수 로그와 수신 연결을 확인합니다. 이 버튼의 성공만으로 서버 푸시 수신까지 검증되지는 않습니다.

같은 채팅방 알림을 갱신할 때에도 다시 알리도록 `renotify: true`를 사용합니다. 실제 팝업·소리 표시는 브라우저 지원과 OS 알림 설정에 따릅니다. 개발 서버에는 `Chat push skipped: already read`, `subscriptions found`, `accepted by push service` 등의 진단 로그가 표시됩니다. 마지막 로그는 푸시 서비스가 요청을 접수했다는 뜻이며 기기 표시를 보장하지는 않습니다. 새 서비스 워커는 채팅 목록을 다시 열면 업데이트되어 대기 없이 활성화됩니다.

운영과 같은 HTTPS 도메인에서 두 계정으로 로그인합니다. 받는 기기에서 알림을 켜고 홈 화면 웹앱을 닫은 뒤 다른 계정으로 텍스트 및 사진을 보냅니다. 잠금 화면 수신과 알림 클릭 시 올바른 채팅방 이동을 확인합니다. 알림 끄기, 로그아웃, 회원 탈퇴 뒤에는 수신하지 않는지도 확인합니다. iOS 실제 기기의 수신은 데스크톱 테스트로 대체할 수 없습니다.

## 현재 발송 범위

`/api/mutate`의 `message.send`가 저장에 성공한 뒤 Next.js `after()`로 발송합니다. 알림 실패가 채팅 전송을 실패시키지는 않습니다. 중복 요청은 메시지·기기별 DB 제약으로 막고 404/410 구독은 제거합니다. 웹 푸시는 배달·즉시 수신을 보장하지 않습니다.

현재 별도 큐나 주기적 자동 재시도는 없습니다. 네트워크 오류 시 같은 메시지 전송 요청이 재시도되면 다시 발송할 수 있지만, 프로세스 중단 등으로 유실된 발송은 자동 복구하지 않습니다. DB에 직접 입력한 메시지도 발송 대상이 아닙니다. 배달 보장이 더 필요해지면 트랜잭션 아웃박스와 작업 큐를 추가합니다.

`push_deliveries`는 중복 방지용 기록입니다. 구독 삭제·탈퇴 시 연결된 기록도 삭제되며, 장기 운영에서는 보존 기간을 정해 오래된 기록을 정리하세요.
